# Neon Road Rally Web Showcase Plan

## Purpose

Plan how Neon Road Rally should live on `tilthen.app` as both a playable music-driven arcade game and a traffic-driving showcase for original interactive music experiences.

This page should feel public-ready, not like a dev dump. The game remains static, local-first, and browser-playable. The website around it should explain the idea quickly, invite a run immediately, and make the music/game connection feel like the point.

## 1. Public Pitch

### One-Sentence Pitch

Neon Road Rally is a music-driven arcade racer where short seeded road challenges turn original songs into fast local competition.

### Short Website Hero Pitch

Original songs become fast, replayable road challenges in Neon Road Rally, a local-first arcade racer built for quick solo runs, shared seeds, and pass-the-keyboard party competition.

### Social Post Pitch

Neon Road Rally turns original songs into 90-second arcade road challenges. Pick a seed, race the same road, pass the keyboard, and see who survives the music-shaped pressure.

### Plain-English Explanation For Normal Visitors

Neon Road Rally is a browser racing game you can play right away. Each run uses a road seed, so the same song, track, mode, and seed can recreate the same challenge. That makes it easy to compete locally: one person races, then the next person tries the same road and chases the score.

## 2. Page Goal

The page should not merely host the game. It should frame Neon Road Rally as a small but serious music-first arcade product:

- A playable music experience where the road changes pace like a song.
- A local party racer that works for quick pass-the-keyboard competition.
- A seeded challenge machine where the same seed creates the same run.
- An original soundtrack showcase where songs can become roads, challenges, and shareable events.

The page should make visitors understand the hook before they press play: this is not just a canvas racer embedded on a website. It is a repeatable music challenge format.

## 3. Recommended URL

### Option A: `/games/neon-road-rally`

Pros:

- Clearly places the game inside a future TilThen games or interactive music catalog.
- Leaves room for future games, experiments, and soundtrack-driven playable showcases.
- Signals that this is a product page, not a one-off file.
- Works cleanly with related routes such as `/games`, `/games/neon-road-rally/play`, and `/games/neon-road-rally/challenges`.

Cons:

- Slightly longer URL.
- Less direct if used verbally.

### Option B: `/neon-road-rally`

Pros:

- Short, memorable, and strong for social sharing.
- Treats Neon Road Rally like a flagship standalone project.
- Easy to print, say, or place in a video caption.

Cons:

- Uses top-level route space that may become crowded.
- Does not naturally group with future playable music projects.
- Less clear that TilThen may eventually host multiple games.

### Recommendation

Use `/games/neon-road-rally` as the canonical route.

When the game is ready for broader public promotion, add `/neon-road-rally` as a short redirect to the canonical page. That keeps the product architecture clean while preserving a simple marketing URL.

## 4. Page Structure

### Hero

Goal: sell the premise in one screen and give visitors a clear play action.

Content:

- Product name: Neon Road Rally.
- Tight pitch built around music, seeded roads, and local competition.
- Primary action: Play Now.
- Secondary action: See Featured Challenge.
- Support note: best with a desktop or laptop keyboard.
- Background/media: actual game footage, a playable canvas preview, or a real screenshot from Sunset Highway or Redline Run. Avoid abstract gradients or generic neon art.

### Play Game

Goal: make the game immediately playable without losing page context.

Content:

- Embedded game area.
- Fullscreen button or open-game button.
- Keyboard support note.
- Local-save note.
- Audio-on reminder if browser autoplay requires user interaction.

### Featured Challenge Seed

Goal: give first-time visitors a specific reason to play now.

Content:

- Challenge name.
- Track.
- Race type.
- Mode.
- Seed.
- Difficulty.
- Short reason to try it.
- Button: Play Featured Challenge.

Default first feature: Redline Warmup.

### Track/Song Spotlight

Goal: connect the game to music instead of treating audio as background.

Content:

- Sunset Highway as the current primary song-backed track.
- Redline Run as the speed-first track with dedicated song placeholder/fallback status.
- Short "songs become roads" explanation.
- Race sections: Launch, Groove, Pressure, Breather, Final Push.
- Future track cards for additional songs once current tracks are polished.

### Controls

Goal: let visitors start without searching.

Content:

- Arrow keys or WASD: steer.
- Space: boost.
- Enter: start or confirm.
- Esc: pause/back.
- F: fullscreen.
- M: mute/unmute music.
- N: mute/unmute SFX.

Keep this compact. The page should not look like a manual.

### Game Modes

Goal: show that the game has more than one use case.

Content:

- Solo / Seeded Run.
- Challenge Mode.
- Party Mode.
- Fuel Run.

Each mode should get a short visitor-facing card with a direct use case.

### Party Mode Explanation

Copy:

Party Mode is pass-the-keyboard competition. Pick local players, lock a shared seed, and let each driver take a run on the same road. Best of 3 and Total Score formats turn one laptop into a fast room-friendly racing contest.

Important framing:

- Local only.
- No online multiplayer promise.
- Same seed means fair side-by-side comparison.
- Fast handoffs matter more than ceremony.

### Challenge Mode Explanation

Copy:

Challenge Mode uses curated fixed seeds with clear goals. Everyone gets the same road, same mode, and same pressure, so the challenge is easy to replay, compare, and feature on the website.

Important framing:

- Fixed seeds.
- Named challenges.
- Track, race type, mode, seed, objective, and saved best.
- Strong bridge to future Featured Challenge Top 20 leaderboards.

### Fuel Run Explanation

Copy:

Fuel Run changes the pressure: staying alive is not enough. You have to chase gas cans, manage risk, and keep the run going while the road keeps tightening.

Important framing:

- Opt-in race type.
- Different scoring/pressure from Classic.
- Works well as a demo because visitors understand the rule instantly.

### Local Save / Leaderboard Note

Copy:

Scores, profiles, cars, challenge progress, and local leaderboard entries are saved in this browser only. No account is required. Clearing browser data may erase progress.

### Soundtrack / Music Note

Copy:

Neon Road Rally is built around original music. Sunset Highway already has dedicated race music, and Redline Run is staged for its own song while currently falling back to the Sunset Highway track. Future songs should become their own roads, not just menu background music.

### Future Updates

Goal: show momentum without overpromising.

Content:

- Featured challenge rotation.
- Redline Run song completion.
- More refined track cards.
- Optional global Featured Challenge Top 20 later.
- PWA/app packaging later.
- Touch/mobile controls later.

## 6. Featured Seeds

Feature 3-5 challenges first. These should be actual curated challenge names so visitors can find them in the game.

| Challenge | Track | Race Type | Mode | Seed | Why It Is Good For Demo |
| --- | --- | --- | --- | --- | --- |
| Redline Warmup | Redline Run | Classic | Arcade | `REDLINE-WARMUP` | Best first feature. It shows the faster Redline identity without making the first public challenge too punishing. |
| Redline Dare | Redline Run | Classic | Turbo | `REDLINE-DARE` | Good social challenge. The 75% progress goal gives players a reachable dare even if they cannot finish Turbo yet. |
| Fuel Panic | Redline Run | Fuel Run | Pro | `FUEL-PANIC` | Best Fuel Run showcase. It explains the fuel mechanic quickly and makes the race type feel distinct from Classic. |
| Party Seed Sampler | Sunset Highway | Classic | Pro | `PARTY-SEED` | Best room-play seed. It is designed for side-by-side local comparison and future Party Mode promotion. |
| The Dare | Redline Run | Classic | Turbo | `THE-DARE` | Strong retry-loop challenge. It is hard, readable, and easy to frame as a bragging-rights seed. |

### Suggested First Featured Challenge

Lead with Redline Warmup.

Reason: it introduces the newer speed-first Redline identity, uses a real named challenge, has a clean seed, and is easier to recommend publicly than a brutal dare or a fuel-specific challenge.

## 7. Music Integration

The website should make the music/game relationship visible and concrete.

### Core Framing

Use this idea repeatedly:

Songs become roads.

That does not mean beat-matching, rhythm-game timing, or audio analysis. It means each track can have a racing identity, visual mood, pressure curve, and challenge set shaped around the song.

### Sunset Highway Song Notes

Visitor-facing copy:

Sunset Highway is the current main song-backed road: a bright, high-speed arcade drive with traffic, boosts, ramps, hazards, and a pressure curve that rises like a track arrangement.

Planning notes:

- Treat Sunset Highway as the proof-of-concept track for "song becomes road."
- Keep it polished and easy to understand.
- Use it for first-run onboarding and party comparison.
- Do not hide that it is the current primary complete music track.

### Redline Run Song Placeholder

Visitor-facing copy:

Redline Run is the speed-first road, tuned for cleaner high-speed pressure. Its dedicated song slot is planned; until that track is final, it can use the current race music fallback.

Planning notes:

- Be honest that Redline Run is staged for its own song.
- Do not imply a completed Redline song if the final audio is not ready.
- Position it as a preview of how additional songs can become new roads.

### Race Sections

The page should explain the five race sections in plain terms:

- Launch: the run opens and teaches the road.
- Groove: the road settles into its main rhythm.
- Pressure: traffic and decisions tighten.
- Breather: a short release before the end.
- Final Push: the song-road peaks and the run asks for commitment.

Visitor-facing copy:

Each road is shaped like a song: Launch, Groove, Pressure, Breather, and Final Push. The game does not ask you to tap to the beat. It turns the energy of a track into racing pressure.

### Future Song/Track Cards

Each future track card should include:

- Track name.
- Song status: included, preview, or planned.
- Race identity.
- Best first challenge.
- Best party seed.
- Supported race types.
- A one-line "what this road feels like" description.

Do not add a third track before Sunset Highway and Redline Run are polished enough to carry the public page.

## 9. Future Global Leaderboard Note

Do not implement this for the first showcase launch.

### Public Copy For Later

Global Featured Challenge leaderboards are planned for selected seeds. The first version will be optional, limited, and focused on fair comparison instead of open-ended profiles.

### Strategy

Start with Featured Challenge Top 20 only:

- One challenge at a time.
- Same track.
- Same race type.
- Same mode.
- Same seed.
- Same game version.
- No all-time global board across unrelated modes.

Use constrained public racer tags:

- Format: 3 uppercase letters followed by 2 numbers.
- Example: `AAA01`.
- No freeform public names.
- No emoji, HTML, punctuation, spaces, or custom profile text.

Submission should be optional:

- Local scores still work if the player never submits.
- No account required for the first version.
- No cloud save.
- No public display of local player names or car names.

Server validation later:

- Validate score shape, game version, challenge id, race type, mode, seed, finish status, elapsed time, and debug-speed status.
- Rate-limit submissions.
- Reject impossible scores and times.
- Store minimal data.
- Future stronger validation can replay input against the seeded Road Director.

## 11. Website Embed Strategy

### Option A: Iframe / Embed Standalone Game

Description:

Host the current game as a static page and embed it inside the TilThen showcase page.

Pros:

- Preserves the current local-first game with minimal coupling.
- Reduces risk of breaking game input, audio, canvas sizing, saves, or fullscreen behavior.
- Keeps future game updates easy to test as a static bundle.
- Lets the TilThen page own the public framing while the game remains self-contained.

Cons:

- Fullscreen and keyboard focus need careful testing.
- Analytics or page state around the game may be less direct.
- Styling inside the game remains separate from the TilThen page.

### Option B: Direct Route Integration

Description:

Move the game into the TilThen app route as native components and shared app code.

Pros:

- Most integrated page feel.
- Easier shared navigation, layout, and app-state handling.
- Potentially cleaner future in-app links.

Cons:

- Highest risk of accidental game behavior changes.
- Could disrupt audio, input focus, canvas sizing, local storage keys, or fullscreen behavior.
- Pulls a self-contained game into the app build before that coupling is necessary.

### Option C: Static Build Folder Under Public Assets

Description:

Copy the working static game into a versioned public folder, such as `public/games/neon-road-rally/`, and serve it as a standalone game bundle.

Pros:

- Strong fit for the current plain HTML/CSS/JavaScript game.
- Keeps relative assets and audio predictable.
- Easy to deploy on a static host.
- Easy to test with the existing web demo checklist.
- Good base for iframe embedding or an "open full game" link.

Cons:

- Requires a manual or scripted copy step when the game updates.
- The game and showcase route still need coordinated QA.

### Option D: Future PWA

Description:

Make Neon Road Rally installable with service worker caching, app icons, offline support, and home-screen install behavior.

Pros:

- Better app-like presentation later.
- Useful for repeat players.
- Could support offline local play once caching is verified.

Cons:

- Too early for first showcase integration.
- Adds caching complexity that can make updates confusing.
- Needs more QA across mobile/tablet/desktop.

### Recommended First Approach

Use a static build folder under public assets, embedded from a TilThen route.

Recommended structure:

- Canonical page: `/games/neon-road-rally`.
- Static game bundle: `/games/neon-road-rally/play/` or `/static/games/neon-road-rally/`.
- Showcase route owns hero, page copy, featured seeds, notes, and future update sections.
- Game remains a self-contained static bundle loaded in an iframe or opened in a focused play view.

This gives the public page strong product framing without pulling the game into TilThen app internals too early.

## 12. Launch Checklist

Before publishing the showcase:

- Reset or curate local demo data in the browser used for screenshots and capture.
- Verify audio files load from the deployed path.
- Verify car and traffic assets load from the deployed path.
- Verify there are no console errors or warnings on first load.
- Verify desktop fullscreen behavior.
- Test Solo / Seeded Run in Classic.
- Test Solo / Seeded Run in Fuel Run.
- Test Challenge Mode with at least Redline Warmup and Fuel Panic.
- Test Party Mode with 2 players.
- Test Best of 3 if included in the public flow.
- Test Total Score if included in the public flow.
- Verify local leaderboard entries save and display.
- Verify local data reset still requires visitor action and does not auto-clear.
- Verify README and security notes remain accurate.
- Verify `WEB_DEMO_CHECKLIST.md` is still aligned with the shipped build.
- Verify no `.DS_Store` files are uploaded or deployed.
- Verify the page copy does not promise online leaderboards, accounts, cloud saves, mobile touch controls, or app-store packaging.
- Verify desktop, iPad with keyboard, and mobile portrait messaging is clear.
- Verify the featured challenge copy matches actual in-game challenge names, modes, and seeds.
- Verify the Redline Run music wording is honest if dedicated Redline audio is not final.
